OWASP Top 10:2025 — A Practical Security Checklist for Your Website

The OWASP Top 10 is the industry’s list of the most critical web application security risks. Here is the 2025 edition in plain language — and what to check on your own site for each one.

By Abdul Rafey31 October 2026

What is the OWASP Top 10?

The Open Worldwide Application Security Project (OWASP) publishes the Top 10 from real-world vulnerability data and practitioner surveys. It is the baseline most security audits and penetration tests are measured against. The 2025 edition adds two new categories — software supply chain failures and the mishandling of exceptional conditions.

The list, with a checklist for each

A01:2025 — Broken Access Control

Users can do or see things they should not, such as opening another customer’s invoice by changing an ID in the URL.

  • Enforce permissions on the server for every request — never rely on hidden buttons.
  • Deny by default; test every user role, including logged-out visitors.

A02:2025 — Security Misconfiguration

Default passwords, debug mode in production, open cloud storage, missing security headers.

  • Turn off debug output and directory listing; remove sample files.
  • Send security headers (CSP, HSTS, X-Frame-Options) and review cloud permissions.

A03:2025 — Software Supply Chain Failures

New in 2025: compromised or vulnerable libraries, plugins, build tools and update channels.

  • Keep an inventory of dependencies and plugins; remove what you do not use.
  • Update promptly and install only from trusted, maintained sources.

A04:2025 — Cryptographic Failures

Sensitive data sent or stored without strong encryption.

  • Use HTTPS everywhere with HSTS; never store plain-text passwords — use a slow hash such as bcrypt or Argon2.

A05:2025 — Injection

Untrusted input interpreted as code: SQL injection, cross-site scripting (XSS), command injection.

  • Use parameterised queries and output encoding; validate input on the server.
  • A strict Content-Security-Policy limits the damage of any XSS that slips through.

A06:2025 — Insecure Design

Flaws in the logic itself — for example, a password reset that can be guessed, or a checkout that trusts prices sent by the browser.

  • Threat-model important features before building them; rate-limit sensitive actions.

A07:2025 — Authentication Failures

Weak login, session and credential handling that enables account takeover.

  • Offer multi-factor authentication; block brute-force and credential-stuffing attempts.
  • Expire sessions properly and use secure, HttpOnly cookies.

A08:2025 — Software or Data Integrity Failures

Trusting code or data without verifying it — unsigned updates or insecure deserialisation.

  • Verify integrity (signatures, checksums) of updates and third-party scripts; protect your CI/CD pipeline.

A09:2025 — Logging & Alerting Failures

Attacks go unnoticed because nothing is logged — or nobody is alerted.

  • Log logins, failures and admin actions; alert on suspicious spikes and review regularly.

A10:2025 — Mishandling of Exceptional Conditions

New in 2025: applications that fail unsafely under errors or unexpected input — leaking stack traces or “failing open” and granting access.

  • Show generic error pages to users and log details privately; make failures deny access, not grant it.

Where to start

For most small business websites, the quickest wins are updating every plugin and library (A03), adding security headers and removing debug settings (A02), and turning on multi-factor authentication for every admin account (A07).
